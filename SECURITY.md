# Security policy

Do not include passwords, authentication tokens, private account data, join
codes, or participant contact information in a public issue.

ALCL never needs an EA account password or authentication token. Anyone asking
for those credentials while claiming to represent ALCL should be treated as
fraudulent.

Until a private security contact is configured, do not deploy this development
build with real participant data. The production operator must replace this
section with a monitored private reporting channel and response policy.

Security-sensitive changes should include tests for authorization, RLS,
validation, audit behavior, and historical-data integrity.
